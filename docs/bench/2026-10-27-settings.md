# Settings window on SettingsKit (2026-10-27)

`FrameScrubBench settings [--rounds N] [--settle MS] [--shots DIR] [--start ID]` (Sources/FrameScrubBench, after
LoupeBench's): the real window and all 12 pages over an empty framescrub.conf and input.conf in a temp dir, on screen.
A round goes down the sidebar to the last page and back (22 switches, one ↓ / ↑ key event each, then 1.5 s of run loop).
Main-thread CPU (`CLOCK_THREAD_CPUTIME_ID`): per switch in all, and the longest run loop turn after it (how long a click
or key waits at worst). Kit: SettingsKit 0.6.0 + the `settings` branch (SettingsOverride, KeyBindingStep).

Machine: Mac16,6, Apple M4 Max, macOS 27.0.1 (26A434), shared with other builds; runs at load average < 5, 3 runs.
Not measured on an Intel Mac (none at hand).

The rounds after the first stay flat (1160, 1172; 1151, 1164; 1190, 1141): nothing accumulates.

## Loupe on the same Mac today

Loupe's own document (2026-10-26-settings-instant.md, same kit 0.6.0) has returns of 10–16 ms and rounds of 250–265 ms.
LoupeBench settings `--icons 0` built from Loupe's `main` and run right after FrameScrub's runs: returns 35–62 ms, rounds
856–941 ms (20 switches), opening 590 ms. FrameScrub's ~52 ms per return is Loupe's level: the difference from the
10-26 numbers is in the kit or the system, not in FrameScrub's pages.

Where a return's time goes (`sample` over rounds 2–3, FrameScrub): about a third is the window's drag margins —
`NSWindow _resetDragMargins` → `NSThemeFrame _opaqueFullSizeContentViewRegionWithClipRect:` →
`NSHostingView.acceptsFirstResponder` → SwiftUI `FocusNavigator.firstNavigableItem`, a walk of the responder tree of
the nested hosting views on each display cycle after a switch; then SwiftUI's graph update (~30 %, the `PageStack`
show/hide and the cards' material layers made again for the page shown), AppKit layout (~10 %) and the window title
(~5 %).

## Open

- The drag-margin walk is SettingsKit's (glass style, full-size content view) and costs Loupe the same: to be fixed in

- Opening the window is at the 300 ms budget on the M4 Max (more on a loaded run); Loupe's is 590 ms.
