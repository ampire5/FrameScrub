# Home step 2: HomeView with Recent and Stash — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the start screen (`HomeScreenView`) becomes HomeScreenKit 0.5's `HomeView`:
- a sidebar with Recent and Stash;
- Recent as a source of video cards with resume progress, grouped by date;
- Stash's library as an app page;
- Home over a paused video with ⇧⌘H, and back with ⌘[ / Esc.

**Architecture:**
- Core (`FrameScrubCore/HomeRecent.swift`) turns the recent URLs, `ResumeStore` and `HiddenRecent` into `BrowserEntry`s. It is pure and tested.
- The app (`FrameScrub/FrameScrubHomeSource.swift`) is the one `HomeSource`. It serves `.source("recent")` and `.source("stash")` and hands clicks and menus to `PlayerWindowController` through closures.
- `PlayerWindowController` makes `HomeView` once, keeps it hidden and parked when not shown, and swaps the window's toolbar.

**Tech Stack:** Swift 6.2 (Swift 5 mode), AppKit, Swift Testing, HomeScreenKit 0.5.0.

**Spec:** `docs/superpowers/specs/2026-10-26-home-screen-kit-design.md` (sections Window, Source, Config, Plan step 2)

## Global Constraints

- Main-thread budgets (CLAUDE.md): Home show ≤ 300 ms the first time, video ↔ Home ≤ 100 ms; nothing synchronous on the main thread (reachability and thumbnails stay async as today).
- HomeView is made once and only hidden afterwards (`isParked = true`), never removed or rebuilt.
- No migrations:
  - `start-tab`, `start-card-size` and `home-layout` are removed;
  - new keys: `home-tab` (`recent` | `stash`, default `recent`), `home-card-size` (60…480, default 220), `recent-count` (1…200, default 50), `home-sidebar` (bool, default true).
- Single window: every `HomeClick` opens in this window.
- Card ids: `recent:<path>`. Source ids: `recent`, `stash`.

## Review Focus

1. **A recent file on an unreachable share** must not block anything: the card is dimmed after ≤ 1 s, as today (`PathAvailability.check`). Pinned by `HomeRecentTests.dimsUnreachable`.
2. **Stash not configured, but `home-tab=stash` is saved:** Home opens on Recent and the sidebar has no Stash row. Pinned by `HomeRecentTests.stashTabFallsBackToRecent`.
3. **Remove from Recent while Recent is shown:** the card goes at once (listing reloaded) and the hidden list survives a relaunch. Pinned by `HomeRecentTests.hiddenAreLeftOut`.
4. **⇧⌘H with nothing open:** the same as the start screen, with no crash on `core.url == nil`. Manual check in Task 4.
5. **A failed open** (`failedURL`) shows Home with a toast plus the OSD reason, and Return on Home does not reopen the failed file. Manual check in Task 4.

### Task 2: App — FrameScrubHomeSource

**Files:**
- Create: `Sources/FrameScrub/FrameScrubHomeSource.swift`

**Interfaces:**
- Consumes: `HomeRecent` (Task 1).
- Produces: `@MainActor final class FrameScrubHomeSource: HomeSource` with
  - `weak var view: HomeBrowserView?`;
  - `init(recentURLs: @escaping () -> [URL], resume: ResumeStore, thumbnails: ThumbnailStore, thumbnailer: RecentThumbnailer, stashPage: @escaping () -> NSView?, hasStash: @escaping () -> Bool)`;
  - `var onOpen: ((URL) -> Void)?`;
  - `var onMenu: ((URL, String) -> Void)?`, where the item ids are `finder`, `copy` and `remove`, as `recentMenuChosen` has them today.

How each `HomeSource` member behaves:
- `list(.source("recent"))` yields the entries at once, then again with the unreachable dimmed after `PathAvailability.check(paths, timeout: .seconds(1))`, only if any. Same shape as Loupe's `HomeCollections.recentListings`.
- `list` of anything else finishes empty.
- `places()` → `[]`.
- `folders(in:)` → `[]`.
- `parent(of:)` → `.source("recent")`.
- `symbol` → `"film"`.
- `wantImages(ids, width:)`:
  - for each id: `thumbnails.image(for:)` on a `.utility` task, then `view?.setImage`;
  - the ids still without a picture go to `thumbnailer.start(jobs)`, the existing serial `.utility` queue, which today feeds `showRecentCards`;
  - a new `wantImages` replaces the previous jobs (the thumbnailer cancels them itself).
- `menu` → Show in Finder, Copy Path, Remove from Recent.
- `perform` → `onMenu`.
- `open` → `onOpen` (all `HomeClick`s).
- `rename` / `trash` throw `CocoaError(.featureUnsupported)`; they are unreachable, since `canRename` and `canTrash` are false.
- Sort: `sort(for:)` defaults to date descending; `setSort` keeps it for the run.
- `info`:
  - `recent` → `HomeSourceInfo(title: "Recent", sortKeys: [.date, .name], groupsByDate: true, noun: "video", emptyHint: "Drop a video here or press ⌘O")`;
  - `stash` → `HomeSourceInfo(title: "Stash", page: stashPage())`.
- `sidebar()`:
  - section `library`: Recent (`clock`);
  - section `stash` when `hasStash()`: Library (`server.rack`).

### Task 3: PlayerWindowController — HomeView replaces the start screen

**Files:**
- Modify: `Sources/FrameScrub/PlayerWindowController.swift`. Every `startScreen` use (listed in the spec) changes:
  - `startScreen: HomeScreenView` becomes `home: HomeView?` plus `homeSource: FrameScrubHomeSource?`, made by `makeHome()` on the first show;
  - `showStartScreen(tab:)` becomes `showHome(tab:)`;
  - `showRecentCards` and `recentItems` go;
  - `resizeStartCards` becomes `resizeHomeCards`, which saves `home-card-size`;
  - `showStartTab` and `makeStashLibrary` change: the Stash page is no longer added to the window. It is `stashPage()` for the source, the same `StashLibraryView` made lazily;
  - `handleKey`: on Home, `home.browser.handleKey(event)` first;
  - the side buttons: `SideButtonFilter.startScreenPress` → `homePress`. Back / Forward move the browser's history (`goBack` / `goForward`) unless the Stash page shows with `mx-side-buttons=take`, which keeps today's `.pageBack` / `.pageForward`.
- Modify: `Sources/FrameScrub/AppDelegate.swift`: View › Home (⇧⌘H), Toggle Sidebar (⌃⌘S); the card size items check `showsHome`.
- Modify: `Sources/FrameScrub/Preferences/PreferencesView.swift`: the Home layout picker goes; a Home group gets the Show sidebar toggle and the Recent count stepper.
- Modify: `Sources/FrameScrubCore/SideButtonFilter.swift`:
  - rename `startScreenPress` → `homePress`;
  - add the `.browserBack` / `.browserForward` outcomes.
- Test: `Tests/FrameScrubCoreTests/SideButtonFilterTests.swift`, updated for `homePress`.

**Interfaces:**
- Consumes: `FrameScrubHomeSource` (Task 2), `HomeRecent` and the Config keys (Task 1).
- Produces:
  - `func showHome(tab: HomeTab? = nil)`;
  - `func hideHome()`;
  - `var showsHome: Bool`.

  The AppDelegate and the menus call these.

Behaviour that is decided here:
- **`showHome`:**
  - if a file is open: `core.pause()`, keeping the file open;
  - attach the view once, full size, over `videoView` and below the slots (`SlotsController(container:above:)` gets `home` as the view it sits above);
  - `isHidden = false`, `isParked = false`;
  - `window.toolbar = home.browser.nsToolbar`, `titlebarAppearsTransparent = true`, `titleVisibility = .hidden`;
  - hide the seek bar, HUD and OSD;
  - `browser.cardSize = config.homeCardSize`, `isSidebarVisible = config.homeSidebar`;
  - `browser.show(.source(shownTab))`, or `reload()` if it is already there;
  - first responder: the browser (the Stash page focuses itself).
- **`hideHome`:**
  - `isHidden = true`, `isParked = true`;
  - `window.toolbar = nil`, title visible again;
  - first responder: `videoView`.
- Opening a file from Home (`onOpen`) calls `openFile(url)`, which already hides the start screen; that place now calls `hideHome()`.
- ⌘W / the end of the playlist: `showHome()` where `showStartScreen()` was.
- ⌘[ and Esc on a paused video with Home made: `showHome()`. Esc keeps its current meanings first (leaving full screen, closing popovers); this is only its last fallback.
- **A failed open:** `showHome()`, then `home.browser.showToast("Cannot open <name>")`. The reason and hints go to the OSD (`showMessage`, 6 s) as today.
- `onLocation`: saves `home-tab` only for the user's own moves (a `movingForApp` flag around `showHome`'s own `show`).
- `onWindowText`: sets the window title while Home shows.

## What changed while doing it (2026-10-26)

- **The kit.** HomeScreenKit `home` (on top of `polish`: Finder's toolbar and path bar, the card-size slider) adds
  `FileStyle`:
  - `.videos` gives 16:9 slots, "videos" in the counts, and the entry's own line in a chip with its progress as a
    track on the picture;
  - a source's date groups of files are laid out as files.

  FrameScrub builds against it in edit mode (`swift package edit HomeScreenKit --path ../HomeScreenKit-home`) until
  `polish` and `home` are merged and released (docs/kits.md).
- **Why a file failed** is not a toast: `OpenFailureView` keeps today's message (title, reason, detail, keys) over
  the video, with Return to retry.
- **Esc on Home** goes back to the open video through a local key monitor: the browser and the window keep Esc to
  themselves. ⌘[ on a video shows Home; ⌘[ on Home is the browser's own Back.
- **Showing Home over a video** saves its position and picture first, so its Recent card is current.
- ⌘= / ⌘− and File › Larger / Smaller Cards go by the kit's four sizes (`largerSize` / `smallerSize`).
